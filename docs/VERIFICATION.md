# 验证记录

验证日期：2026-11-07。验证环境：Windows、Python 3.13.9、内置 Chromium 浏览器。

## 自动化测试

执行 `python -m unittest discover -s tests -v`，13 项测试全部通过。

- 金额精度：0.10 + 0.20 = 0.30；拒绝零、负数、超过两位的小数、非数值和非有限值。
- 日期与类别校验：拒绝不存在的日期、错误格式和与收支类型不匹配的类别。
- 新增、编辑、删除后重新实例化服务，验证 JSON 持久化结果。
- 日期和金额区间包含边界；多个条件取交集；明细与汇总一致。
- 损坏 JSON、重复 ID 会阻止读取，保留原文件。
- 模拟替换文件失败，确认磁盘和内存记录不变，临时文件被清理。
- 外部修改不会被当前服务覆盖。
- HTTP 增删改查、静态资源、错误输入、缺失记录与访问限制。
- CSV 导出接口：筛选结果条数、UTF-8 BOM、中文表头、金额两位小数、逗号/引号/换行转义、公式注入防护、空结果只有表头、非法参数返回 400。

## CSV 导出按钮验证

在 `GET /api/records.csv` 与账目明细「导出 CSV」按钮完成后，用 14 条演示记录（每页 8 笔）在 Edge 146 无头浏览器中通过 CDP 驱动执行 19 项检查，全部通过：

- 首屏只显示 8 笔，导出文件为 14 行，确认按全部匹配记录导出而不是当前页。
- 文件带 UTF-8 BOM，表头为「日期、收支类型、类别、金额（元）、备注」，文件名为 `account-book.csv`。
- 备注中的逗号、双引号、换行按 CSV 规则往返；`=1+1` 开头的备注导出为 `'=1+1`。
- 按类别「交通」筛选后导出 4 行，与筛选结果一致；导出后筛选条件和列表保持不变。
- 最低金额 99999 无匹配结果时仍下载只含表头的 CSV，并提示「已导出空表头」。
- 连续点击三次只产生一个下载；开始日期非法时提示「导出失败：开始日期格式应为 YYYY-MM-DD，且必须是真实日期」。
- 390 × 844 视口下页面无整体横向溢出，按钮在视口内可点击并成功导出；浏览器控制台无错误。
- 验证使用独立测试账本与临时下载目录，未写入正式账本。

另通过 `node --check static/app.js` 与 Python 编译检查。Node.js 仅用于开发验证，运行软件不需要安装。

## 一句话记账验证

验证日期：2026-11-07。验证环境：macOS、Python 3.13、Node.js（仅用于 `node --check`）。

- 合并最新 main（含备份恢复）后执行 `python -m unittest discover -s tests -v`，28 项测试全部通过；其中一句话记账新增 11 项。
- 解析规则覆盖：相对日期（昨天、前天、N 天前、周几、上周几）与具体日期；时间（12:30、下午3点）不会被当作金额；数量词（3杯）不会被当作金额；“15块5”；全角输入；收入关键词与“发红包”排除；找不到类别时归入“其他”并提醒；多个数字时优先带“元/块/¥”的数字并提醒；无金额、日期不存在、金额为 0、超过两位小数、超过 100 字均返回可读错误。
- 接口测试确认 `POST /api/quick-parse` 不改变账本记录数，返回的草稿可以直接作为新增记录保存；非对象请求体和 GET 请求分别返回 400、404。
- 合并 main 之前，在独立测试账本 `.qa/quicktest/ledger.json` 上做过浏览器实测：识别并预填、保存后列表与汇总刷新、空输入与无金额提示、取消后保留原句、普通“记一笔”与“编辑记录”不受影响、375 px 宽度无横向溢出。实测中修复了窄屏输入框溢出和识别金额缺少千位分隔符两处问题。
- 合并 main 之后的前端只重新执行了 `node --check static/app.js`，尚未在浏览器中重新实测。
- 修复 `tests/test_backup.py` 在 macOS 上的误报：临时目录 `/var` 实际指向 `/private/var`，测试改为比较解析后的路径，Windows 上结果不变。
